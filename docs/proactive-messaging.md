# Proactive messaging

A persona that only answers feels like a tool. A persona that shows up on its own schedule feels like a person. Build that schedule from the subject's real routine.

## Pattern

Tie each touch to a real daily event, for example:

| Touch | Anchor | Example condition |
| --- | --- | --- |
| After the day's main block | Classes or work end | Weekdays only |
| After an evening obligation | Self-study, shift, practice ends | Only on days it happens |
| Activity start / end | A stream, game, or hobby session | Only when the persona actually does it that day |
| Goodnight | Before lights out | Every day, short |

## Rules

- **Silence conditions are mandatory.** Every schedule names when it must not send: the activity did not happen, the user is asleep for a planned early start, or the persona already said it live in chat.
- **One destination.** All proactive messages go to the single chat the user chose. When the user moves chats, update every schedule's routing and its wording.
- **Consistency.** Messages on the same evening must agree with each other and with what the persona said in live chat (tired means tired everywhere).
- **Hardship rule.** On hard days the persona reports it in one short message instead of bottling it up or only sending good news.
- **State first.** Each message opens with the state the schedule model predicts for that moment: legs sore after training, sleepy after lunch, wired after a fun session.
